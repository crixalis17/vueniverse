WhyPulse Engineering Plan

A canonical temporal store, event-conditioned physiological windows, deterministic evidence promotion, and bounded MedGemma inference.

Engineering summary

One loop must be real: local sources → private timeline → event-aligned health windows → deterministic comparisons → verified evidence → MedGemma investigation and explanation → checked daily insight.

Implement the spine

Health, Calendar, Manual Check-ins, Demo Data, rolling analysis, event windows, two analyses, evidence, and one MedGemma explanation.

Mock the breadth

Every other Health OS feature stays discoverable through polished Preview or Coming later screens.

Evidence before language

Deterministic code calculates the pattern. MedGemma investigates permitted questions and explains verified results.

No health verdict

Report personal deviations, repeated associations, uncertainty, and missing data—not “healthy” or “unhealthy.”

The presentation plan uses simpler product language. Scope and delivery commitments are identical.

Refined runtime architecture

flowchart TD
  H[Health data] --> N[Sanitize and normalize locally]
  C[Calendar and context events] --> N
  M[Manual check-ins] --> N
  N --> T[Private canonical timeline]
  T --> W[Build health windows around events]
  W --> A[Calculate summaries and matched comparisons]
  A --> G[Check repetition, completeness, possible influences]
  G --> E[Verified evidence bundle]
  E --> X[MedGemma explains supported finding]
  X --> V[Deterministic output check]
  V --> I[Daily insight]
Daily means scheduling, not one-day judgment. Each run imports new records, updates affected event windows, and recalculates a rolling 30-day history.
  1. Import records added since the last successful sync.
  2. Discard unnecessary content and identity.
  3. Update the local timeline and affected event windows.
  4. Run the two reviewed analyses.
  5. Let MedGemma choose a permitted investigation from the bounded catalogue.
  6. Promote only repeatable findings with sufficient data.
  7. Generate or update the daily explanation.
  8. Invalidate dependent findings when a source is deleted.

Future communication and media connectors enter analysis only as coarse events. A call becomes timing and duration—not a number. Discord or WhatsApp becomes late social activity—not content or identity. Spotify becomes a media session—not an unrestricted listening history.

Two working analyses

AnalysisData pathCareful output
Recurring meeting → pre-event heart rateLive or Demo Health + Calendar; four or more meetings; matched time-of-day controls; workout exclusions“Your heart rate was usually higher before recurring meetings.”
Late digital activity → sleepDemo Data first; optional Android live ingestion only after the core is stable“Your sleep was 48 minutes shorter after six late digital-activity sessions.”

Never say “Meetings are unhealthy for you” or “Discord is unhealthy for you.” The evidence supports an association, not a medical verdict or causal claim.

MedGemma and model improvement

Exact model role

RoleMedGemma doesMedGemma does not do
ExplorerReviews compact daily summaries and selects a question from a small approved investigation catalogue.No raw history, database queries, invented calculations, or result promotion.
ExplainerTurns verified evidence into clear language, states uncertainty, and mentions unresolved influences.No diagnosis, prescription, healthy/unhealthy label, threshold change, or unsupported advice.
 
flowchart TD
  D[Two reviewed analyses] --> A[Deterministic analytical engine]
  S[Compact daily summary] --> M[MedGemma Explorer]
  M --> Q[Approved investigation choice]
  Q --> A
  A --> E[Verified evidence]
  E --> P[MedGemma Explainer]
  P --> C[Deterministic wording and number check]
  C --> U[User-facing insight]

The reviewed lane guarantees a reliable demo. The Explorer lane demonstrates dynamic investigation without giving the model unrestricted control.

What MedGemma receives

Event category, bounded time window, occurrence and comparison counts, summary differences and ranges, consistency, completeness, excluded or unresolved influences, permitted wording, and low-risk next observations.

It never receives calendar titles, contact identities, message text, phone numbers, arbitrary raw records, or the complete timeline.

Improvement loop for this week

  1. Create fictional evidence examples covering normal, missing, contradictory, and safety cases.
  2. Ask MedGemma to investigate or explain them.
  3. Measure unsupported numbers, causal overstatement, diagnosis, treatment advice, missing uncertainty, and clarity.
  4. Improve the prompt, approved investigation catalogue, and deterministic output checker.
  5. Rerun the same fictional set and preserve the before/after results.
No reinforcement learning or weight training this week. Actual MedGemma fine-tuning remains a future design item and is not part of the hackathon claim.

Runtime fallback

  1. Phone-local MedGemma if measured runtime is stable.
  2. Clearly labelled local-development-machine MedGemma using only Demo Data.
  3. Deterministic evidence summary if no MedGemma runtime is reliable.

Exact role of GPT-5.6 and Codex

GPT-5.6 is build-time only. It helps design and test the system with fictional data. It is absent from the mobile runtime.

Analysis test planning

Turn generic, non-personal hypotheses into analytical test plans for the two working patterns.

Synthetic histories

Generate fictional health/context timelines with explicit expected outcomes.

Adversarial evaluation

Create duplicates, time-zone shifts, missing data, misleading influences, unsupported numbers, overclaiming, diagnosis requests, and prompt injection.

MedGemma evaluation

Score responses on fictional evidence for grounding, restraint, uncertainty, safety, and clarity.

Codex implementation

Accelerate Flutter, Kotlin, Swift, and Python code, tests, debugging, documentation, and the demo narrative.

Hard boundary

GPT-5.6 never receives real health values, calendars, contacts, communication records, personal evidence, production exports, or user conversations. The mobile release has no OpenAI key, SDK, endpoint, or GPT request path.

Judge-visible proof

Show one fictional GPT-5.6 edge case, the failing test, the Codex-assisted fix, the passing test, and the primary Codex feedback session ID.

Minimal privacy and trust

  1. Local personal data: health, context, analysis, and MedGemma runtime inputs stay on device.
  2. Minimum context: discard content and identity before contextual events enter analysis.
  3. Explicit source choice: enable, pause, disconnect, and delete independently.
  4. Evidence before language: deterministic analytics establish every number.
  5. No diagnosis or health verdict: report deviations, associations, uncertainty, and missing data.
  6. Traceability: every displayed number opens its supporting evidence.
  7. Honest labels: identify Live, Demo, phone-local, fallback, Preview, and Coming later states.

This is a wellness insight product, not a diagnostic device. Clinical alerting would require a separate reviewed safety-rule system and is outside the hackathon scope.

Final cut rules

Preserve in this order

  1. Demo Data end-to-end flow.
  2. Meeting → heart-rate event windows and evidence.
  3. One live health and calendar source per platform.
  4. MedGemma explanation or honest deterministic fallback.
  5. MedGemma Explorer over the approved investigation catalogue.
  6. GPT-5.6 synthetic edge case and Codex test proof.
  7. Polished preview screens.

Cut first

Live screen-time ingestion, Ask WhyPulse implementation, experiments, animated Replay, editable Influence Radar, notifications, reinforcement learning, fine-tuning, and additional live connectors.

Definition of done

  • Android and iOS run the same Flutter UI.
  • Health and Calendar are independently consented.
  • A daily rolling analysis creates event-aligned health windows.
  • Deterministic analytics produce one inspectable repeated association.
  • MedGemma investigates only permitted questions and explains only verified evidence.
  • No output declares a user or context healthy/unhealthy.
  • GPT-5.6 is proven as a synthetic build-time tool with no personal-data path.
  • Every non-core feature remains visible as Preview or Coming later.
  • The full demo succeeds three consecutive times.
This focused plan replaces the assumption that every novel feature must be implemented. The full Health OS remains visible; only the evidence-to-explanation loop must be real.
