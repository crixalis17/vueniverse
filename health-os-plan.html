One-week hackathon · Flutter-first · Android + iOS

Private Health OS

One Flutter product that joins health, schedule, behaviour, and self-reported context into private, evidence-backed health explanations.

Summary and decision

Flutter owns the entire product experience. Dart provides every screen, state model, timeline, insight, journal, and evidence rule. Kotlin and Swift exist only at the operating-system edge: health stores, calendars, permissions, background work, secure keys, and model-runtime integration.

One UI

Compose the dashboard, timeline, sources centre, journal, experiments, privacy controls, and evidence views once in Flutter.

One private timeline

Normalize all source records into a provenance-rich canonical event model stored locally and encrypted.

Evidence before AI

Analytics create an evidence card. Local MedGemma writes the explanation but is not allowed to invent the pattern.

Local learning

A contextual bandit learns insight timing and tone from helpfulness feedback without retraining the LLM.

The analysis engine establishes the pattern. MedGemma receives the bounded evidence card, not raw life data; it returns a schema-validated observation, uncertainty, and one reversible low-risk experiment.

  ios/Runner/              # HealthKit, EventKit, Keychain, entitlements
  native/inference_runtime/# optional C/C++ FFI model backend

Use a package/plugin first where it is reliable; otherwise use a custom Pigeon bridge. Reserve FFI for a local C/C++ model runtime, where avoiding message serialization matters.

Builder ABuilder BDefinition of done
Android Calendar Provider, Usage Stats summary, timeline provenance chips.iOS EventKit, then Core Motion only after EventKit works.Health plus calendar appears on both timelines; Android may add app-use intervals.

Do not pass raw calendar titles to the model. Categorise locally into values such as meeting, recurring_one_to_one, travel, or social_plan.

Day 4 — Evidence engine, no LLM

Late screen use → sleep

Compute app-use duration in the two hours before sleep. Require four late nights, a 30-minute sleep difference, and 70% data completeness before creating a card.

Recurring meeting → HR

Compare median HR in the 15 minutes before a recurring meeting with comparable no-meeting windows. Require four meetings, an 8 bpm effect, and 60% directional consistency.

Builder B writes these algorithms as pure Dart with seed-fixture tests. Builder A builds the Home insight card and Evidence Detail screen. The user must be able to see repeat count, effect, alternatives, and data sources.

Day 5 — Safe MedGemma gateway

Builder ABuilder BDefinition of done
Implement LocalModelGateway, loading/error state, structured-JSON validator, and insight renderer.Run the device model spike; build exact prompt with evidence JSON, prohibited claims, and output schema.An evidence card becomes a validated observation, caveat, and reversible experiment.

Fallback ladder: phone-local MedGemma → smaller honest local model → clearly labelled development-machine inference → deterministic evidence explanation. Never sacrifice evidence integrity for an LLM demo.

Day 6 — Local learning, privacy, and resilience

Implement a local Thompson Sampling bandit with actions show_now, evening_reflection, weekly_review, and suppress. Rewards are helpful, acted, snoozed, and dismissed—not time in app. Add Journal, source toggles, provenance, delete-local-data action, and a seed/live demo switch.

Day 7 — Rehearse the actual story

Run clean installs on both phones. Test permission denied, no health data, missing calendar, duplicate sync, and model unavailable. Rehearse the full demonstration three times with the seed fallback available at launch. Record a backup demonstration before submission.
