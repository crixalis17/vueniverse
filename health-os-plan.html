WhyPulse

Your health changed. Let’s find out why—privately, with evidence, alternative explanations, and a personal experiment.

Summary and decision

Flutter owns the entire product experience. Dart provides every screen, state model, timeline, insight, journal, and evidence rule. Kotlin and Swift exist only at the operating-system edge: health stores, calendars, permissions, background work, secure keys, and model-runtime integration.
Zero-personal-data GPT-5.6: GPT-5.6 is a build-time Detector Architect and synthetic red-team evaluator. It receives schemas, fictional hypotheses, synthetic fixtures, code, and test results—never PII, real health values, contacts, calendars, or derived personal evidence. The mobile release has no OpenAI key, SDK, endpoint, or GPT network path.

One UI

Compose the dashboard, timeline, sources centre, journal, experiments, privacy controls, and evidence views once in Flutter.

One private timeline

Normalize all source records into a provenance-rich canonical event model stored locally and encrypted.

Evidence before AI

Analytics create an evidence card. Local MedGemma 1.5 writes the explanation but cannot invent the pattern.

Model jury

Deterministic code verifies every number and claim; GPT-5.6 red-teams synthetic cases while personal data remains local.

Winning thesis and novelty

Pitch: WhyPulse connects all the health data a person chooses to make available with the moments around it, shows the evidence and alternative explanations, and helps them run a private experiment to learn what improves their health.

Detector Architect

GPT-5.6 converts a generic hypothesis into signals, windows, controls, confounders, falsifiers, thresholds, and allowed claim level—without seeing records or values.

Synthetic cohort generator

Every fictional timeline carries synthetic: true, a synthetic_* subject, reproducible seed, generated timestamps, and expected outcome.

Adversarial red team

GPT-5.6 designs time-zone, duplicate, missing-data, confounder, contradictory-metric, and fictional prompt-injection cases.

MedGemma evaluator

GPT-5.6 scores only synthetic MedGemma drafts against a fixed rubric; deterministic verification and a human remain the release gate.

Boundary rules

  1. Write product rules once in Dart; do not duplicate detectors, evidence, experiments, or reinforcement policy in Kotlin and Swift.
  2. Native Kotlin/Swift retrieves platform records in typed batches and never decides health insights.
  3. Python and OpenAI dependencies stay inside tooling/gpt_lab/ and never enter the release bundle.
  4. Use C/C++ only for a measured inference-runtime need, not normal business logic.
  5. An optional judge web build comes from Flutter/Dart; do not create a separate JavaScript frontend.
  6. Do not add Java, Objective-C, Rust, React Native, or TypeScript during the week unless unavoidable generated glue requires it.

This week: contextual bandit around MedGemma

A contextual bandit chooses one allow-listed action and learns from feedback. It personalizes delivery—not medical truth. The evidence engine, MedGemma weights, Claim Verifier, detector thresholds, confidence, and safety rules remain outside its control.

  positive → alpha += rewardWeight
  negative → beta += abs(rewardWeight)
  snooze → update preferred-time bucket only

Bandit guardrails

  • Cannot alter evidence, confidence, detector thresholds, diagnosis/causal policy, care escalation, or Claim Verifier.
  • Cannot invent experiments; it selects only reversible actions from experiment_allow_list.json.
  • Cannot suppress deterministic safety information.
  • Feedback and parameters remain local, never train MedGemma, and are deleted on reset.
  • Every choice stores action, eligible alternatives, policy version, and a local explanation.

This remains STRETCH. Cut it before cutting Replay, Evidence Receipt, Claim Verifier, MedGemma, or the N-of-1 experiment.

Changing MedGemma weights happens offline on synthetic or specifically licensed reviewer-created examples. It requires GPU training, safety evaluation, model versioning, and a human release gate; it never runs continuously on the phone.
